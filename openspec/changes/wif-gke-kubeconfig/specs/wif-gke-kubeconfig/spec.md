## ADDED Requirements

### Requirement: GKE kubeconfig via WIF
When `ENABLE_GCP_WIF=1` and `K8S_CLUSTER_NAME` is set, `create_kubeconfig()` SHALL generate a kubeconfig for the specified GKE cluster using `gcloud container clusters get-credentials`, leveraging the gcloud authentication already established by `create_wif()` earlier in the `before_script` chain.

#### Scenario: Kubeconfig generated with required variables
- **WHEN** `ENABLE_GCP_WIF=1`, `K8S_CLUSTER_NAME`, `K8S_LOCATION`, `GCP_PROJECT_ID`, and `KUBE_NAMESPACE` are all set
- **THEN** `create_kubeconfig()` SHALL call `gcloud container clusters get-credentials $K8S_CLUSTER_NAME --location $K8S_LOCATION --project $GCP_PROJECT_ID` and produce a valid kubeconfig

#### Scenario: Kubeconfig missing required GKE variables
- **WHEN** `ENABLE_GCP_WIF=1` and `K8S_CLUSTER_NAME` is set but `K8S_LOCATION`, `GCP_PROJECT_ID`, or `KUBE_NAMESPACE` is missing
- **THEN** `ensure_deploy_variables()` SHALL print a descriptive error message and exit with code 1

### Requirement: Namespace-scoped kubeconfig
After cluster credentials are fetched, `create_kubeconfig()` SHALL scope the active kubeconfig context to `$KUBE_NAMESPACE` so that all `kubectl` commands default to that namespace.

#### Scenario: Default namespace set to KUBE_NAMESPACE
- **WHEN** `create_kubeconfig()` completes the WIF+GKE path
- **THEN** `kubectl config set-context --current --namespace=$KUBE_NAMESPACE` SHALL have been executed and `kubectl get pods` SHALL list only pods in `$KUBE_NAMESPACE`

#### Scenario: Cross-namespace access is not the default
- **WHEN** the kubeconfig has been generated by the WIF+GKE path
- **THEN** `kubectl get pods` (without `-n`) SHALL return results from `$KUBE_NAMESPACE` only, not from `kube-system` or other namespaces

### Requirement: DNS endpoint support
When `K8S_USE_DNS_ENDPOINT=1`, `create_kubeconfig()` SHALL append `--dns-endpoint` to the `gcloud container clusters get-credentials` command to enable DNS-based cluster access for private GKE clusters.

#### Scenario: DNS endpoint flag appended when enabled
- **WHEN** `K8S_USE_DNS_ENDPOINT=1`
- **THEN** the `gcloud container clusters get-credentials` command SHALL include the `--dns-endpoint` flag

#### Scenario: DNS endpoint flag omitted when not enabled
- **WHEN** `K8S_USE_DNS_ENDPOINT` is unset, empty, or `"0"`
- **THEN** the `gcloud container clusters get-credentials` command SHALL NOT include the `--dns-endpoint` flag

### Requirement: WIF+GKE path called after GitLab Agent setup
In the `before_script` chain, `create_kubeconfig()` (WIF+GKE branch) SHALL be called after `setup-gitlab-agent()` so that the gcloud-based context becomes the final active kubeconfig context when both are configured.

#### Scenario: gcloud context overrides agent context
- **WHEN** both `setup-gitlab-agent()` and the WIF+GKE `create_kubeconfig()` path execute in the same job
- **THEN** the active kubectl context after `before_script` completes SHALL be the one produced by `gcloud container clusters get-credentials`
